# Размещение GM и рейтинг модернизации PTP

Самостоятельный код для задач 2 и 3. `ptp/solver.py` содержит размещение
минимального числа GM и выбор пакетов модернизации. `ptp/data.py` читает GraphML
и явные параметры из JSON. `ptp/__main__.py` предоставляет командную строку.
`ptp/path_ranking.py` содержит отдельный эвристический вариант для больших сетей;
команда `ranking` использует точную MILP-модель из `solver.py`.

## Быстрый запуск

Нужен [Pixi](https://pixi.sh/). Команды выполняются из корня этой папки:

```powershell
pixi install --locked
pixi run placement
pixi run ranking
pixi run test
```

Готовый искусственный пример находится в `examples/demo.graphml` и
`examples/demo.json`. Результаты команд появятся в `results/demo/placement.json`
и `results/demo/ranking.json`. Если Pixi нет, установите Python 3.13,
`networkx`, `numpy` и `scipy`; затем используйте команды `python -m ptp` ниже.

## Свои данные

В GraphML у каждого узла нужны `site_name` (площадка) и `net_type` (`RRN` или
`MBH`). В JSON укажите путь к GraphML относительно самого JSON, параметры,
список БС и **каждое** исходное ребро. Полный пример структуры —
`examples/demo.json`. БС может быть несколько на одном узле; каждая запись
`stations` потребляет одну единицу ёмкости GM. GM-кандидат — узел MBH с
оптическим линком.

При неполном GraphML сначала создайте шаблон и заполните в нём недостающие
важности БС, стоимость, тип и статус всех линков, а также локальную задержку:

```powershell
pixi run python -m ptp audit path\to\network.graphml --output results\audit
```

Шаблон будет в `results/audit/input.template.json`. Скопируйте его в свой
`input.json`, исправьте путь `graphml` и заполните поля со значением `null`.
Недостающие значения программа не выдумывает.

```powershell
pixi run python -m ptp placement path\to\input.json --output results\placement.json --seconds 120
pixi run python -m ptp ranking path\to\input.json --placement results\placement.json --output results\ranking.json --seconds 120
```

`--seconds` ограничивает **один** запуск MILP, а не полное время работы.
`ranking` использует уже выбранные положения GM; назначение основной/резервный
GM для отдельных БС может меняться. `--max-packages` ограничивает число групп
рейтинга.

## Что учитывает модель

- Каждой обслуживаемой БС нужны пути к основному и резервному GM на разных
  оптически связанных площадках. `optical_rule` в JSON задаёт связь между
  площадками: `path` или `direct`.
- Задержка каждого пути не выше `max_path_delay_us`. Вместимость GM включает БС
  любых площадок и проверяется в штатном режиме и при отказе любого **одного**
  GM. Отказы линков и площадок отдельно не моделируются.
- Изолированные площадки перечисляются в предупреждении и исключаются из
  расчёта. Несвязанные компоненты с несколькими площадками сохраняются.
- Линки с `cost = 0` готовы с начала. Эффект модернизации БС появляется только
  после готовности **обоих** путей. Группа выбирается по максимуму прироста
  важности на единицу стоимости; внутри группы линки показываются по стоимости,
  затем по ID.

Статус `OPTIMAL` относится к конкретному размещению или следующей группе при
доказанном решении MILP. Весь последовательный рейтинг не объявляется
глобально оптимальным для произвольного бюджета. При лимите времени результат
имеет соответствующий статус без неподтверждённого утверждения об оптимальности.
